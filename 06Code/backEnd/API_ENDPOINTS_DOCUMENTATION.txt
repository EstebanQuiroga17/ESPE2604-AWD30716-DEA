Full System Documentation: ATS Express
System Endpoints & Resource Architecture

Overview
This document contains the complete URI mapping for the entire ATS Express software system deployed in production on Microsoft Azure. It covers three main areas in alignment with our microservices architecture:
• Part 1 — Business Logic API Endpoints: Server-side routes that encapsulate domain logic, authentication, SRI tax validations, file processing (XML, ZIP, PDF), and return structured JSON responses.
• Part 2 — CRUD Persistence & Repository API Endpoints: Server-side repository routes interacting directly with our PostgreSQL database via Prisma ORM and Supabase, strictly protected by internal API keys.
• Part 3 — Frontend Page URIs: Client-side single-page application (SPA) routes that render our interfaces and dashboards in the browser.

====================================================================================================
PART 1
Business Logic API Endpoints
Server-side routes · JSON responses · https://ats-business-rules-service-angel-czefcghef8c3bcca.eastus2-01.azurewebsites.net
====================================================================================================
Overview
The Business Logic Service acts as our primary application gateway and orchestrator in production on Azure. It verifies JWT authorization tokens, validates RUC structures against official Ecuadorian Internal Revenue Service (SRI) algorithms, handles asynchronous batch operations, generates PDF RIDE documents, packages XML invoices in memory into ZIP archives, and securely routes data requests to our persistence layer via an automated Circuit Breaker design pattern.

Base URL
The primary production base URL for all Business Logic API requests is:
https://ats-business-rules-service-angel-czefcghef8c3bcca.eastus2-01.azurewebsites.net

Server-side routes · JSON responses · https://ats-crud-service-angel-czefcghef8c3bcca.eastus2-01.azurewebsites.net

Overview
The CRUD Persistence Service deployed on Microsoft Azure directly manages database communication with our Supabase PostgreSQL relational instance via the Prisma Object-Relational Mapper (ORM). This layer implements an explicit Strict Repository Pattern: no external frontend application or user interface is permitted to invoke these endpoints directly. Only internal cluster calls originating from our Business Logic Service bearing an authorized `X-API-Key` header are accepted.

Base URL
The primary production base URL for all CRUD Repository API requests is:
https://ats-crud-service-angel-czefcghef8c3bcca.eastus2-01.azurewebsites.net

Mandatory Security Protection for Repository Routes (/repo/*)
• Required HTTP Header: X-API-Key
• Expected Header Value: Internal application secret matching environment variable INTERNAL_API_KEY.
• If this key is missing or incorrect, our API Key middleware immediately aborts processing and rejects the request with HTTP 401 Unauthorized or HTTP 403 Forbidden.

Error Codes (CRUD Repository API — Part 2)
----------------------------------------------------------------------------------------------------
This persistence API uses the following repository error codes:
HTTP Code    Description
400 Bad Request           The repository received malformed JSON payloads or missing required primary database insertion fields.
401 Unauthorized          The request attempted to access repository routes without providing the mandatory X-API-Key HTTP header.
403 Forbidden             The X-API-Key secret provided in the request header did not match our internal server security environment variable.
404 Not Found             A specific UUID primary key targeted for update, reading, or deletion was not found in our relational PostgreSQL tables.
500 Internal Server Error An unexpected Supabase database constraint violation or network communication breakdown occurred during query execution.
